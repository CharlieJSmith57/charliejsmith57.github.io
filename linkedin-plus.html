LinkedIn+

LinkedIn shows you one profile at a time. I wanted to see the whole network: who moved where, which companies cluster, and which connections are real relationships rather than inferred ones. So I built a pipeline that maintains that picture for me every day.

What it does

LinkedIn+ is a private, self-hosted “network intelligence” tool for one account: mine. Each day it pulls a fresh copy of my connections through LinkedIn’s own data-export feature, notices what changed, fills in the companies it doesn’t know yet, classifies every title, and rebuilds a graph I can explore in a browser. It’s a personal instrument, not a product, and it lives entirely on my machine.

How it runs unattended

ExportA browser session requests the LinkedIn data archive.
WatchAn IMAP watcher spots the “your archive is ready” email.
DiffThe new CSV is compared with the last snapshot; only changes move on.
EnrichCompany lookups and a title classifier add industry, discipline and seniority.
PublishExcel is the master store; a JSON export feeds the graph.

The three parts live in three separate folders on purpose: orchestration, enrichment, and data. That split is a hard rule in the codebase, and it’s what let me rebuild the enrichment stage from scratch in August without touching a single row of data.

The graph

The front-end is a static page fed by network.json. It has five views (network, company, industry, school, discipline) in 2D and 3D, with company clustering and an org-chart layout driven by seniority. Two classifiers I wrote from scratch make those views possible: a 17-tier discipline-by-seniority title taxonomy that turns free-text job titles into something sortable, and a four-tier Greek-organization detector covering 68 organizations and roughly 8,400 chapter-name variants.

The biggest upgrade was adding mutual-connection data. Before it, “these two people know each other” was inferred from shared schools and employers. After it, the graph carries more than 15,900 confirmed relationship edges, so the clusters you see are real.

The bug that took a month

In July 2026 LinkedIn changed its data formats. Nothing errored; the import simply started writing empty fields, and I didn’t notice until the daily diffs went quiet. Fixing it meant rebuilding the parser and, more importantly, building a 46-record regression corpus so I could prove the new import matched the old one byte for byte before trusting it again. Silent failures are worse than loud ones; the pipeline now has a watchdog that flags a run whose output is emptier than yesterday’s.

Data

The pipeline runs on my own data, requested through LinkedIn’s standard data-export feature the way any member can. Everything stays on my machine: the public repository holds the code and the visualization, not the workbook, and the graph is a private tool, not something I publish.
